# Universal-Public-Transport-Booking-System
Mobility as a Service (MaaS) system with the integration of multiple transport modes with journey information and payment functions in one service.

## Scenario
We are a small software company proposing a universal public transport booking system that allows users to search, compare, book and manage bus, train and taxi journeys through a single application. To demonstrate the idea, our team must develop a functioning end-to-end prototype using realistic, simulated data and clearly defined system boundaries.

## Stakeholders and Interactions
| Stakeholder | Primary interest | Interaction Spec |
| :--- | :--- | :--- |
| **Passenger** | Plan, book and manage journeys | Search routes, compare options, reserve a seat or taxi, pay through a payment service, and retrieve a digital ticket. |
| **Transport operator** | Publish and manage services | Maintain routes, schedules, fares, capacity, vehicle or service status, and disruption information. |
| **System administrator** | Operate the platform securely | Manage accounts, providers, configuration, audit records and system-wide reports. |
| **Support staff** | Resolve booking issues | Find a booking, record a case, and process a cancellation or refund according to defined rules. |

## What our system should do
### Journey planning and booking
* **Multimodal Transit:** Should support seamless planning and booking across multiple transport modes including **bus, train, and taxi services**.
* **Flexible Routes:** Should handle both single-mode trips and complex, multi-leg **multimodal journeys** in a single itinerary.
* **Dynamic Updates:** Needs to account for real-time operational factors such as fluctuating **fares, seat availability, sudden cancellations, delays**, and route changes to minimise user friction.

### Stakeholder and data management
* **Targeted Functionality:** Should provide specialised tools and dashboards tailored to each identified stakeholder (passengers, transport operators, admins, support staff).
* **Data Integrity:** Will be able to securely manage all critical platform data, including **user accounts, journey histories, and booking transactions**.
* **Information Design:** Must present complex journey options, booking confirmations, and service alerts in a **clear, accessible, and intuitive manner**.

### Standards
* **Non-Functional Compliance:** System should address essential requirements surrounding **usability, accessibility, data privacy, and robust security protocols**.
* **Working Prototype:** Must be able to deliver a fully functioning, end-to-end prototype demonstrated using **realistic, production-grade test data**.
* **Engineering Rigor:** Must ensure the system architecture is backed by comprehensive **automated/manual testing** and thorough **technical documentation**.
